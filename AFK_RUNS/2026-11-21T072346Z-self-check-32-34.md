### #32 halt

The issue requires every minted name to be fresh against all names minted earlier in the module while also requiring unchanged generated output. A measurement shows these conflict. I temporarily made `freshNameWhere` reserve each returned name for the rest of the module (reset in `setUserNames`), logged every mint, and ran `lsc gen` for both backends over `examples/*.ts`:

- 74 example files changed (1000+ / 1003− lines).
- 1121 of 1781 mints returned a different name: narrowing binders from condition facts 525, `matchBinder` 349, the per-function `res` 195, the `_x_idx` pair minted by resolve and transform 43, other 9.
- `arrayContains`, `containsDuplicate`, `spec` and `toposort` reference `_x_idx` in invariants and would stop verifying.
- In `todo-domain` one binder would receive 47 primes.

The halt comment offers three designs (a region-scoped supply, recommended; module-wide reservation that accepts the output change; proving only the pure rule) and asks the owner to choose. The experiment patch and mint log are kept in the run's scratch directory. The worktree was restored and nothing from the experiment is committed.
