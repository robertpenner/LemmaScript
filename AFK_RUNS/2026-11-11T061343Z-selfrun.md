### Findings

Every suspected bug, with its current status, is also tracked in the running bug log [2026-11-11T061343Z-selfrun-bugs.md](2026-11-11T061343Z-selfrun-bugs.md).

- **#2, compiler bug (fixed in `87d2d72`, upstream-ready branch `upstream/indexed-callbacks`):** array callbacks that read the element index (`xs.every((e, i) => ...)`, `some`, `map`) emitted Dafny that failed to resolve (`Unknown` index type, `Seq.All` arity mismatch, 2-parameter lambda applied to one argument) or that silently dropped the index binder in `some`. Brief: https://github.com/robertpenner/LemmaScript/issues/2#issuecomment-6788826048
- **#2, observation, not fixed:** `a.slice(1)` lowers to `a[1..]`, which Dafny rejects unless `|a| >= 1`; JavaScript returns `[]` for an empty array. The result is sound, but valid code is rejected.
- **#2, observation, not fixed:** inline anonymous record types (for example `{name: string; value: TExpr}[]`) all lower to one opaque `type i__type(==)`, so distinct inline record types share a name. The output resolves.

- **#4, compiler bug (fixed in `12ba2d1`):** `BigInt(n)`/`Number(n)` resolved to an unknown type, so a `bigint | null` return emitted the integer without a `Some` wrap.
- **#4, garbage output (fixed in `c0706d4`):** `BigInt(s)` on a string was lowered as the identity and produced a string where Dafny expects an int. `transform` now rejects it.
- **#4, toolchain gap (fixed in `6ead9ea`):** `Number.isSafeInteger` lowers to the 2^53 - 1 bound for integer arguments.
- **#4, deferred:** `decimalNumberLiteral` and `exactIntegerLiteral` are `//@ extern` in `ir.ts` (double formatting and `BigInt(string)` parsing are outside the model). Details: https://github.com/robertpenner/LemmaScript/issues/4#issuecomment-6789115576
- **#4, observation, not fixed:** with `//@ autohavoc`, a returned havoc of unknown type emits `var t: Unknown := *; return t;`, which fails Dafny type checking. `main` already behaves this way.

- **#5, toolchain gap (fixed in `287c7a1`):** string `lastIndexOf` had no Dafny lowering. Lean keeps rejecting it. Testing showed that Dafny cannot prove literal string disequalities without per-index hints, so the JavaScript comparison compiles and runs the Dafny instead.
- **#5, garbage output (fixed in `652516f`):** an indexed access type annotation (`T["k"]`) was emitted as a Dafny type name. Details: https://github.com/robertpenner/LemmaScript/issues/5#issuecomment-6789509731
- **#5, observation, not fixed:** every inline anonymous record type collapses to the one opaque `type i__type(==)`.

- **#3, known bug, fixed upstream by open PR midspiral/LemmaScript#242:** a presence check guarding the rest of an `&&`/`||` chain used as a value (`o !== undefined && x < o`, `o === undefined || o + 1 > x`, and the `if`/ternary forms) emits the raw `Option`. Recorded as `KNOWN_BUGS` in `narrow-checks.test.ts`.
- **#3, check gap found and closed:** in `if (o === undefined || o + 1 > x) return 1;`, narrow binds `o` correctly, but `o + 1` keeps the optional type that `resolve` stamped before narrowing, and `transform` lowers the comparison as `match (v + 1) { case Some… }`. The first version of the checks missed it; the stale-arithmetic-stamp rule now catches it. The same shape is in #242's fixture (`orEarlyReturn`).
- **#3, no new bugs on main:** the 87-module corpus has no violations.
