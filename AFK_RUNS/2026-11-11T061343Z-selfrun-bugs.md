### Rediscovered known bugs

The fuzzer found these already-reported bugs without being pointed at them. They show what it can detect, and they are not new reports.

- **midspiral/LemmaScript#230, binder collision.** At `ffc07fc`, `return a_b !== undefined && a.b !== undefined ? a_b + a.b : -1;` and the reverse order bind both paths to `_a_b_val`. Dafny **accepts** the module, so the compiled function silently adds `a.b` to itself. Only the narrow checks report it.
- **midspiral/LemmaScript#231, guard order.** At `ffc07fc`, `if (box !== undefined && box.inner !== undefined && box.inner.value !== undefined && x < box.inner.value)` reads `inner` from an `Option`. The default run did not reach this shape, because `&&` chains used as values (B7) filled the class limit. A run restricted with `--positions` to `if` and ternary forms found it as class 1. The branch accepts the same module.
- **`if`-condition guards on `main`.** With `--positions`, the branch fuzzer reports `if (o !== undefined && o - x > 0)`, `if (o !== undefined && p !== undefined && x < o + p)` and `if (a.inner !== undefined && a.inner.value !== undefined && x < a.inner.value)` as Dafny rejections. #242 fixes all three, and its tests contain the same shapes.

## Fuzzer defects

Found by the final series review and fixed in `49a19f5`. The fuzzer runs recorded above were made before the fix.

- A replay with `--path` kept shrinking under the plain "module is ok" property, so it could arrive at a class an earlier round had already reported instead of the one printed. Replays now stop at the module the path names.
- The printed replay command left out `--positions`.
- The `checks` signature was not normalized, so the #230 binder collision appeared as two classes (`a_b` inside `a.b`, and the reverse) in the `ffc07fc` runs.
- Rejections were grouped with oracle failures and counted toward the exit status. They are now listed as rejection classes and do not change the exit code.
